Compress → Image

First the text (or any file) is compressed — the engine tries a dictionary coder, an arithmetic coder, and their combination, and keeps whichever is smallest. Then that small result is painted into a picture. A long document becomes a tiny image you can reload to get every byte back.

The compressed data, painted as an image

What this does and doesn't do

The image is small because the data was compressed first. Compression only works on redundancy: long text, logs, JSON, DNA, raw/uncompressed files shrink a lot. Already-compressed inputs (.mp4, .jpg, .zip) are near-random and won't shrink — the engine then stores them raw, so the result is never larger than the input plus a few bytes.

Every result here is lossless: loading the PNG rebuilds the original byte-for-byte, verified live.
